# Sessions

Hermes Agent manages conversation sessions to maintain context, track usage, and handle state across interactions.

## Session Structure

Each session is identified by a unique session key:

```
agent:main:whatsapp:dm:5216567779922
```

Format: `agent:profile:platform:chat_type:chat_id`

| Component   | Description                             |
| ----------- | --------------------------------------- |
| `agent`     | Fixed prefix for all Hermes sessions    |
| `profile`   | Active profile name (e.g., `main`)      |
| `platform`  | Messaging platform (e.g., `whatsapp`)   |
| `chat_type` | Type of chat (`dm`, `group`, `channel`) |
| `chat_id`   | Unique identifier for the conversation  |

## Session Data

Sessions track the following information:

| Field                | Description                                 |
| -------------------- | ------------------------------------------- |
| `session_id`         | Unique identifier for this session instance |
| `created_at`         | When the session was first created          |
| `updated_at`         | Last time the session was active            |
| `display_name`       | User's display name                         |
| `platform`           | Active messaging platform                   |
| `chat_type`          | Direct message, group, or channel           |
| `last_prompt_tokens` | Token count for the last prompt             |
| `estimated_cost_usd` | Estimated cost in USD                       |
| `suspended`          | Whether the session is paused               |
| `resume_pending`     | Whether a resume is waiting                 |

## Suspend and Resume

Sessions can be suspended and resumed:

### Suspending a Session

Use the `/pause` command to suspend:

- Context is preserved
- No new messages are processed
- Use `/resume` to continue

### Resuming a Session

Use the `/resume` command to continue:

- If `resume_pending` is true, the session will pick up where it left off
- `resume_reason` indicates why the session was paused

## Token Tracking

Hermes tracks token usage per session:

- `input_tokens`: Tokens inbound messages consumed
- `output_tokens`: Tokens generated in responses
- `cache_read_tokens`: Tokens from cached context
- `cache_write_tokens`: Tokens written to cache
- `total_tokens`: Combined token count

Cost estimates are calculated based on your model's pricing.

## Auto-Reset

Sessions may auto-reset if:

- Context exceeds the token budget
- Extended inactivity period
- Manual reset requested with `/reset`

When auto-reset occurs, `was_auto_reset` is marked true and `auto_reset_reason` records the trigger.

## Session Management

### Viewing Session Status

Use `/status` to see current session details including:

- Active profile
- Platform and chat type
- Token usage
- Suspend/resume state

### Resetting a Session

Use `/reset` to clear context while keeping the session active. A fresh reset (`is_fresh_reset: true`) indicates no prior conversation history.

### Session Expiry

Sessions finalize after extended inactivity. Set `expiry_finalized: true` to mark a session as complete. The system may retain session metadata for reporting purposes.

## Multi-Platform Sessions

Sessions are platform-specific by default. A WhatsApp conversation and a Telegram conversation maintain separate sessions even for the same user. Cross-platform continuity is not automatic.

## Session Storage

Session data persists in `~/.hermes/sessions/sessions.json`. Do not edit this file directly—use commands or the API to modify session state.
